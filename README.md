# MySQL 连接池项目

连接池采用单例模式设计，实现了连接的主动创建、动态扩容、超时等待、空闲连接的主动回收，并巧妙地利用了 C++ 的智能指针（自定义释放行为）实现了连接的**无感自动归还**。

---

## 💻 开发与运行环境

### 1. 软件环境

- **操作系统**：Arch Linux
- **虚拟机软件**：VMware 20,1 (运行在 Windows 宿主机上，通过 WezTerm SSH 进行开发)
- **编译器**：`g++` (GCC, 支持 C++11 及以上标准)
- **依赖库**：`mariadb-libs` / `mysqlclient` 动态链接库，以及 `pthread` 线程库
- **构建工具**：GNU Make

### 2. 虚拟机硬件分配

- **CPU**：AMD Ryzen 7 4800U (分配 4 核心)
- **内存 (Memory)**：3.78 GiB
- **磁盘 (Disk)**：124.20 GiB (ext4 文件系统)

---

## ⚡ 压力测试设计

测试通过并发向 MySQL 数据库的 `conn-pool` 库中的 `user` 表插入 10,000 条数据，来对比**使用连接池（长连接复用）**与**不使用连接池（频繁建立短连接）**的性能差异。

### 1. 测试条件

- **并发线程数**：4 线程
- **单线程插入量**：2,500 条
- **总插入数据量**：10,000 条
- **测试 SQL**：`insert into user(name,age,sex) values('zhang san', 20, 'male')`
- **计时方法**：使用 C++ 现代时间库 `<chrono>` 测量真实墙上时间 (Wall-clock time)

### 2. 测试配置 (`mysql.ini`)

- `initSize = 10` (初始池大小)
- `maxSize = 1024` (最大池容量)
- `maxIdleTime = 60000` (连接最大空闲存活时间，毫秒)
- `connectionTimeOut = 100` (获取连接超时时间，毫秒)

## 📈 测试结果与性能对比

在本地 VM 虚拟化双层磁盘架构（ext4 over NTFS/APFS）的压力测试下，测试结果如下：

| 指标                 | 不使用连接池 (常规短连接) | 使用连接池 (长连接复用) |     性能变化      |
| :------------------- | :-----------------------: | :---------------------: | :---------------: |
| **总耗时**           |       **8,068 ms**        |      **4,867 ms**       | ⏱️ 缩短 **39.7%** |
| **QPS (每秒请求数)** |         **1,239**         |        **2,055**        | 🚀 提升 **65.8%** |

### 🔍 性能数据深度剖析

1. **为什么提升了约 65.8%？**
   在本地虚拟机测试中，由于客户端和服务端在同一台虚机内，网络延迟（RTT）接近于 0。因此，常规短连接的 TCP 握手损耗并不明显。连接池之所以依然能带来近 1.6 倍的性能增幅，是因为它免去了每次插入时频繁的账号密码认证以及大量的套接字创建和销毁开销。
2. **为什么没有带来数十倍的暴涨？**
   因为当前测试采用的是**单条隐式事务插入（自动提交）**。MySQL 接收到每一条 `insert` 都会触发物理磁盘的 `fsync`（刷盘操作）。在虚拟机双层磁盘的写入瓶颈下，磁盘 I/O 阻塞占了总耗时的 80% 以上。
3. **稳定性优势**：
   在不使用连接池且并发极高时，短连接在大批量快速建立时容易耗尽系统端口或冲垮 MySQL 的 `backlog` 队列，导致抛出 `Lost connection to server (system error: 104)` 错误。而连接池自始至终只维持稳定的长连接，**拥有绝对的生产级稳定性**。

## 🛠️ 编译与运行指南

### 1. 数据库准备

在你的 MySQL 中创建好对应的库和表：

```sql
CREATE DATABASE `conn-pool`;
USE `conn-pool`;

CREATE TABLE `user` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `name` VARCHAR(50) NOT NULL,
  `age` INT NOT NULL,
  `sex` VARCHAR(10) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2. 编译项目

在项目根目录下直接使用 `make` 工具进行编译：

```bash
# 清理并重新编译
make clean && make
```

编译成功后，将在 `bin/` 目录下生成两个可执行文件：

- `bin/test_no_pool`：不使用连接池的测试程序
- `bin/test_with_pool`：使用连接池 the 测试程序

### 3. 配置数据库连接

修改根目录下的 `mysql.ini`，将其中的 `ip`、`port`、`username`、`password` 等参数修改为你本地数据库的真实信息。

### 4. 运行测试

确保 `mysql.ini` 与可执行程序在同一级别目录（或在项目根目录下运行以下命令）：

```bash
# 运行短连接测试
make runn

# 运行连接池测试
make runp
```
